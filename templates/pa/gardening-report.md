# PA Gardening Report Template

PA autopilot uses this template when rendering the daily gardening report into the vault root.
`scripts/pa-autopilot.sh` is the primary caller and writes the rendered note to `{vault}/PA Gardening Report.md`.
This template is a visible operator-facing note, not an internal state file.
It summarizes infrastructure health, steward execution, sync status, and warnings from a single autopilot run.

## Rendering Rules

1. **Placement**: Write the rendered note to `{vault}/PA Gardening Report.md`.
   Do not create alternate filenames unless the caller intentionally overrides the destination.
2. **Run stamp**: Fill `{{date}}` and `{{time}}` from the same autopilot run in the vault timezone.
   Use concrete local values so the note can be correlated with daemon logs.
3. **Overall status**: Resolve `{{overall_status}}` using the fixed values `healthy`, `degraded`, `infra-only`, or `failed`.
   Use the status rules below instead of inventing new run-level labels.
4. **Infrastructure**: Always render `QMD Refresh`, `Shadow Sync`, and `Hash Index` in this order.
   Each row must include a status, duration, and short notes value even when the stage was skipped or failed.
5. **Steward**: Render `{{steward_summary}}` as a compact prose block or bullet list summarizing `/pa steward` output.
   When gardening did not run, state the reason directly in this section.
6. **Sync**: Always render `Pre-sync (pull)` and `Post-sync (push)` in this order.
   If sync was intentionally skipped, record that in the step note instead of removing the row.
7. **Warnings**: Render `{{warnings}}` as a bullet list.
   Include auth failures, posture blocks, stage failures, degraded states, and any condition that prevented normal gardening.
8. **Overwrite semantics**: Treat the report as fully managed by autopilot.
   The caller overwrites the previous report rather than appending to it.
9. **Failure visibility**: Render the report even when the run is degraded or failed if enough data exists to explain the failure.
   Prefer explicit `failed`, `blocked`, or `skipped` values over silent omission.

## Output Format

```markdown
# PA Gardening Report

> Last run: {{date}} {{time}}
> Status: {{overall_status}}

## Infrastructure

| Stage | Status | Duration | Notes |
|-------|--------|----------|-------|
| QMD Refresh | {{qmd_status}} | {{qmd_duration}} | {{qmd_notes}} |
| Shadow Sync | {{shadow_status}} | {{shadow_duration}} | {{shadow_notes}} |
| Hash Index | {{hash_status}} | {{hash_duration}} | {{hash_notes}} |

## Steward

{{steward_summary}}

## Sync

| Step | Status | Notes |
|------|--------|-------|
| Pre-sync (pull) | {{pre_sync_status}} | {{pre_sync_notes}} |
| Post-sync (push) | {{post_sync_status}} | {{post_sync_notes}} |

## Warnings

{{warnings}}

---
*Generated by PA Autopilot. Do not edit manually — this note is overwritten nightly.*
```

## Render Contract

The caller must replace every `{{placeholder}}` with data from the same autopilot run.
Prefer explicit fallback values over unresolved placeholders.
Render every major section every day so degraded states remain visible.

| Placeholder | Meaning | Fallback |
|-------------|---------|----------|
| `date` | Local calendar date of the autopilot run in the vault timezone | Required |
| `time` | Local wall-clock time of the autopilot run in the vault timezone | Required |
| `overall_status` | Run-level summary derived from the status rules below | `failed` |
| `qmd_status` | Result of `qmd update && qmd embed` | `skipped` |
| `qmd_duration` | Elapsed time for the QMD refresh stage | `n/a` |
| `qmd_notes` | Short note about index refresh outcome, counts, or failure cause | `No additional notes.` |
| `shadow_status` | Result of `pa-shadow.sh sync` | `skipped` |
| `shadow_duration` | Elapsed time for the shadow sync stage | `n/a` |
| `shadow_notes` | Short note about sync scope, changed paths, or failure cause | `No additional notes.` |
| `hash_status` | Result of `pa-mask.sh hash-index` | `skipped` |
| `hash_duration` | Elapsed time for the hash index stage | `n/a` |
| `hash_notes` | Short note about hash regeneration outcome or failure cause | `No additional notes.` |
| `steward_summary` | Summary of gardening work completed by `/pa steward` or the reason gardening was not run | `Steward did not run.` |
| `pre_sync_status` | Result of the pre-gardening pull step | `skipped` |
| `pre_sync_notes` | Short note about pull outcome, conflicts, or why the step did not run | `No pre-sync action recorded.` |
| `post_sync_status` | Result of the post-gardening push step | `skipped` |
| `post_sync_notes` | Short note about push outcome, auth failure, or why the step did not run | `No post-sync action recorded.` |
| `warnings` | Bullet list of run warnings and degraded conditions | `- None.` |

## Status Rules

| Value | Use When |
|-------|----------|
| `healthy` | All required stages that ran completed successfully and no warning requires degraded presentation |
| `degraded` | The report rendered, but one or more stages failed, were blocked, or completed with material warnings |
| `infra-only` | Infrastructure ran, but no gardening was performed and the run intentionally stopped before steward work |
| `failed` | A critical failure prevented normal completion and the report is primarily a failure summary |

## Stage Status Conventions

| Value | Meaning |
|-------|---------|
| `ok` | The step completed successfully |
| `skipped` | The step was intentionally not run |
| `blocked` | A precondition, auth issue, or posture rule prevented the step |
| `failed` | The step attempted work and exited unsuccessfully |
| `degraded` | The step completed partially or produced a usable but weakened result |

## Section Omission Rules

No major section is omitted in this template.
When a section has no content, render its documented fallback instead.
`warnings` should render `- None.` when the run is clean.

## Usage by Script

The calling script (`scripts/pa-autopilot.sh`) is responsible for:

- Running the infrastructure stages and capturing their durations and notes.
- Running `/pa steward` or recording why gardening was skipped.
- Performing pre-sync and post-sync steps when enabled.
- Computing `{{overall_status}}` from the collected stage results.
- Rendering the final note into `{vault}/PA Gardening Report.md`.
- Overwriting the previous report atomically when possible.
